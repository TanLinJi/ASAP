## 1. Purpose / hypothesis

Provide the full KITTI 3D object detection dataset (training + testing splits, ImageSets) under the canonical ASAP path so that every downstream experiment (`E0.3`, `E1.x`, `E2.x`, `E3.x`, `E4.1-E4.2`, `E5.*`, `E6.*`) can run without further data preparation.

Success criterion: file counts and ImageSets entries match the published KITTI 3D object detection benchmark, and `train` / `val` partitions are disjoint and together cover `trainval`.

## 2. Dependencies

- Outbound HTTP access to KITTI servers (for the four zip archives).
- ~30 GB free disk space under `/root/autodl-tmp/ASAP/data/`.
- No upstream experiment; this is a root node.

## 3. Setup

### 3.1 Hardware & environment

- Local disk node, any OS; no GPU required.
- Standard utilities: `bash`, `unzip`, `wget` (or `curl`), `python3`.

### 3.2 Data

Official KITTI 3D Object Detection benchmark, 4 zip packages:

| Archive | Content |
|---------|---------|
| `data_object_velodyne.zip`         | LiDAR point clouds for training + testing |
| `data_object_calib.zip`            | Camera-LiDAR calibration |
| `data_object_label_2.zip`          | 3D detection labels for training only |
| `data_object_image_2.zip`          | Left color images for training + testing |

Plus the standard `ImageSets` split files (`train`, `val`, `trainval`, `test`) sourced from the OpenPCDet repository.

### 3.3 Target layout

```text
/root/autodl-tmp/ASAP/data/kitti/
├── ImageSets/
│   ├── train.txt           # 3712 entries
│   ├── val.txt             # 3769 entries
│   ├── trainval.txt        # 7481 entries
│   └── test.txt            # 7518 entries
├── training/
│   ├── calib/      # 7481 files
│   ├── image_2/    # 7481 files
│   ├── label_2/    # 7481 files
│   └── velodyne/   # 7481 files
└── testing/
    ├── calib/      # 7518 files
    ├── image_2/    # 7518 files
    └── velodyne/   # 7518 files
```

### 3.4 Reproducible command

```bash
cd /root/autodl-tmp/ASAP
bash scripts/prepare_kitti.sh                 # downloads + extracts + ImageSets + verification
# or, equivalently, the individual steps:
bash scripts/download_kitti_object.sh
bash scripts/download_kitti_imagesets.sh
python scripts/verify_kitti_object.py
python scripts/verify_kitti_imagesets.py
```

## 4. Procedure

1. Run `scripts/download_kitti_object.sh` to download the four zip archives into `data/kitti/zips/` and extract them under `data/kitti/training/` and `data/kitti/testing/`.
2. Run `scripts/download_kitti_imagesets.sh` to fetch the four ImageSets split files into `data/kitti/ImageSets/`; the script regenerates `trainval.txt = train.txt + val.txt` to guarantee consistency.
3. Run `scripts/verify_kitti_object.py` to assert that all four subfolders contain exactly 7481 (training) or 7518 (testing) files.
4. Run `scripts/verify_kitti_imagesets.py` to assert that `train`, `val`, `trainval`, `test` have the expected entry counts and that `train ∩ val = ∅`, `train ∪ val = trainval`.

## 5. Expected output

- All four KITTI subfolders populated with the counts in §3.3.
- `ImageSets/train.txt` 3712, `val.txt` 3769, `trainval.txt` 7481, `test.txt` 7518.
- No zip files left under `data/kitti/zips/` if `prepare_kitti.sh` cleans them up (otherwise remove manually to save disk).
- Verification scripts exit with code 0.

## 7. Analysis

Counts match the published KITTI 3D object detection benchmark byte-for-byte; train/val partitions are disjoint and exactly cover trainval; ImageSets are consistent with OpenPCDet's expected splits. The dataset is therefore safe to feed into `E0.3` (info generation) and all downstream experiments.
