## 1. Purpose / hypothesis

Build a single, reproducible `conda` environment named `asap` that satisfies the dependencies of (a) the OpenPCDet detector backend used by `E0.3`-`E4.*`, (b) the ASAP source under `src/asap/`, and (c) the auxiliary scripts under `scripts/`.

Success criterion: `python -c "import pcdet, torch, spconv; torch.cuda.is_available()"` succeeds, `torch.cuda.is_available()` is `True`, and `spconv.__version__` is reported.

## 2. Dependencies

- A working `conda` / `miniconda3` installation.
- Internet access to `pypi.org` and PyTorch's `download.pytorch.org` for CUDA wheels.
- Local NVIDIA driver compatible with CUDA 12.x.
- No upstream experiment.

## 3. Setup

### 3.1 Hardware & environment

- Node with NVIDIA driver supporting CUDA 12.x; the actual runtime CUDA bundled by the conda env is 12.4.
- GPUs: 2 × Tesla T4 (16 GB each) on the development node.

### 3.2 Toolchain

- Python: 3.9.x via conda.
- PyTorch: 2.5.1 with `+cu124` wheel.
- spconv: 2.3.6 (CUDA 12.0 wheel, ABI-compatible with `+cu124` torch).
- numba: 0.60.0 (used by OpenPCDet's KITTI evaluation for rotated IoU; needs `libnvvm.so`).
- `nvidia-cuda-nvcc-cu12`: 12.9.86 (provides `libnvvm.so` + `libdevice.10.bc` consumed by numba's `@cuda.jit`; required by KITTI eval, see Issue (3) below).
- Aux deps (from `requirements.txt`): numpy, llvmlite, tensorboardX, easydict, pyyaml, scikit-image, tqdm, SharedArray, opencv-python, pyquaternion.

### 3.3 Reproducible command

Preferred path (one script, idempotent):

```bash
bash /root/autodl-tmp/ASAP/scripts/create_asap_env.sh
```

Verification:

```bash
conda run -n asap python /root/autodl-tmp/ASAP/scripts/verify_openpcdet_env.py
```

## 4. Procedure

1. Create the `asap` env with `conda create -n asap python=3.9 -y`.
2. Install the CUDA 12.4 PyTorch wheel via `pip install torch==2.5.1+cu124 ...` from `download.pytorch.org/whl/cu124`.
3. Install `spconv-cu120==2.3.6` from PyPI (ABI-compatible with the cu124 torch wheel on this hardware).
4. Install the OpenPCDet Python runtime dependencies listed in `requirements.txt`.
5. Run the verification script to confirm import paths, CUDA availability, and spconv version.

## 5. Expected output

- A populated env at `/root/miniconda3/envs/asap/` with `python` resolving to Python 3.9.x.
- `torch.cuda.is_available()` is `True`.
- `spconv.__version__` resolves cleanly.
- No import error from `pcdet` (after `E0.3` installs it editable).

## 7. Analysis

The env stack is compatible with both the OpenPCDet CUDA extensions (which expect a CUDA 12.x runtime) and with `spconv` 2.3.6 used by most of the OpenPCDet voxel-based detectors. T4 GPUs have enough memory for PointPillars / PV-RCNN inference at `batch_size=4` (KITTI), and should also fit the nuScenes VoxelNeXt / TransFusion-Lidar checkpoints at `batch_size=1..2` for `E1.3 / E1.4 / E4.3 / E4.4`. The deferred Waymo / MPPNet path (`E4.5_deferred_waymo_mppnet.md`) would still benefit from an A100 / H100 node if it is ever re-activated.

## 8. Issues encountered & resolutions

- **`bare pip install` fails for OpenPCDet build isolation.** Resolution: use `conda run -n asap env ... python -m pip install --no-build-isolation -e third_party/OpenPCDet` (see `E0.3`).
- **`libc10.so` not found at runtime.** Resolution: always set `LD_LIBRARY_PATH` to include `/root/miniconda3/envs/asap/lib/python3.9/site-packages/torch/lib` and `/usr/local/cuda-12.4/lib64` before running any OpenPCDet command.
- **`libNVVM cannot be found` during KITTI evaluation.** The system CUDA install at `/usr/local/cuda-12.4` is runtime-only and does not ship `libnvvm.so`; OpenPCDet's KITTI eval uses `@cuda.jit` for rotated IoU and requires it. Resolution: `pip install nvidia-cuda-nvcc-cu12`, then export the following before launching OpenPCDet `test.py`:
  ```bash
  NVVM_ROOT=/root/miniconda3/envs/asap/lib/python3.9/site-packages/nvidia/cuda_nvcc/nvvm
  export LD_LIBRARY_PATH=/root/miniconda3/envs/asap/lib/python3.9/site-packages/torch/lib:/usr/local/cuda-12.4/lib64:$NVVM_ROOT/lib64
  export NUMBAPRO_NVVM=$NVVM_ROOT/lib64/libnvvm.so
  export NUMBAPRO_LIBDEVICE=$NVVM_ROOT/libdevice
  export CUDA_HOME=/usr/local/cuda-12.4
  ```
- **`conda run -n asap python` silently swallows error output and exits with no log.** OpenPCDet's `test.py` errors during the KITTI eval phase were lost inside `conda run`'s output buffer. Resolution: bypass `conda run` and call the env interpreter directly: `/root/miniconda3/envs/asap/bin/python -u test.py ...`. The `-u` flag forces unbuffered output so the log file captures everything in real time.
