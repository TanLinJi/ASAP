## 1. Purpose / hypothesis

Download the **official OpenPCDet pretrained checkpoints** for every detector consumed by `E1.x` / `E4.x`, so that ASAP can be evaluated *inference-only* without retraining any detector. Each checkpoint must match the exact OpenPCDet config that we will run in `tools/test.py`.

## 2. Dependencies

- `E0.2` (`asap` env, used to verify the checkpoint loads cleanly).
- `E0.3` (`pcdet` installed editable; needed to instantiate the detector for the verification step).
- Internet access to a checkpoint source.

> **Networking note (2026-05-20).** From this autodl node `drive.google.com` is **unreachable** (TCP timeout), so the OpenPCDet README's Google Drive links cannot be `wget`-ed directly. `github.com` + `raw.githubusercontent.com` *are* reachable, so any community mirror of an OpenPCDet checkpoint hosted on GitHub is usable. The integrity of any mirror must then be verified by reproducing the original reported metric inside the matching `E1.x` baseline — see §6 below for the PointPillars round-trip.

**Layout policy (2026-05-21).** Every artefact — dataset, checkpoint, output — lives strictly under `/root/autodl-tmp/ASAP/`. Checkpoints are organised by **dataset** (`kitti/`, `nuscenes/`) regardless of upstream vendor, so paths in attack / eval scripts stay short and uniform. The previous `checkpoints/openpcdet/kitti/` and `checkpoints/nuScenes/` directories were folded into this scheme on 2026-05-21; any old documentation referencing those paths must be considered stale.

The Waymo subdirectory and `mppnet_<tag>.pth` from the original plan have been dropped after the Waymo → nuScenes swap (`E0.5` §3.0). The deferred `E4.5_deferred_waymo_mppnet.md` keeps the rationale on record.

The exact file names follow the OpenPCDet model zoo; whichever name is downloaded should be recorded inside this experiment file once `done`.

### 3.2 Reproducible command (KITTI PointPillars, executed 2026-05-20)

```bash
mkdir -p /root/autodl-tmp/ASAP/checkpoints/kitti

# Community GitHub mirror of the official OpenPCDet PointPillars KITTI checkpoint.
# Upstream link in the OpenPCDet README points to Google Drive, which is unreachable
# from this node. The mirror's git blob SHA is 1ffb848688ed2bbfcfc0a52cf9eec66506b419f8
# (per the GitHub Contents API), file size is 19383576 bytes.
curl -fL --connect-timeout 15 --max-time 180 \
    -o /root/autodl-tmp/ASAP/checkpoints/kitti/pointpillar_7728.pth \
    https://raw.githubusercontent.com/gakkiri/simple-pointpillar/main/openpcdet-office-ckpt/pointpillar_7728.pth

# Sanity load inside the asap env
/root/miniconda3/envs/asap/bin/python - <<'PY'
import torch
ckpt = torch.load("/root/autodl-tmp/ASAP/checkpoints/kitti/pointpillar_7728.pth", map_location="cpu", weights_only=False)
print("keys:", sorted(ckpt.keys()))
print("model_state tensors:", len(ckpt["model_state"]))
print("epoch:", ckpt.get("epoch"))
PY
```

For the **other** detectors (PV-RCNN on KITTI, VoxelNeXt and TransFusion-Lidar on nuScenes) the official Google Drive links cannot be reached directly; see §6.2 for the per-detector pending table and §8 for the resolution plan.

## 4. Procedure

1. Identify the OpenPCDet model-zoo entry for each (detector, dataset) pair listed in `paper/detector_selection.md`.
2. Locate a reachable source for the checkpoint (official URL when possible; community GitHub mirror otherwise; record the source explicitly).
3. Download every checkpoint into `checkpoints/<dataset>/` (e.g. `checkpoints/kitti/pv_rcnn_8369.pth`) and record file size, MD5, SHA-256 in §6.
4. Sanity-load each checkpoint inside the `asap` env (`torch.load`), asserting that `model_state` has the expected number of tensors and the key names match the matching config's backbone.
5. **End-to-end verification**: run the corresponding `E1.x` baseline, then compare the resulting per-class AP against the number reported in the upstream README. The checkpoint is considered authentic *iff* every class metric matches within ±0.1 absolute.

## 5. Expected output

- A populated `checkpoints/` directory with the per-dataset subdirectories listed in §3.1.
- A short manifest (this file) recording one row per checkpoint: file path, model-zoo URL, SHA-256, expected metric reported by the original release, the matching config file inside `third_party/OpenPCDet/tools/cfgs/`.

## 7. Analysis

- For KITTI PointPillars, the round-trip `mirror download → torch.load → KITTI eval → AP match to two decimals` is the strongest practical authenticity check we can perform without the upstream signed artifact. Cyclist deviates by 0.07 AP which is within standard CUDA-non-determinism noise on KITTI.
- For nuScenes VoxelNeXt and TransFusion-L, the user-supplied `.pth` files load cleanly into the matching OpenPCDet configs, run inference + nuScenes evaluation end-to-end on `v1.0-mini`, and produce per-class APs in the expected ordering (TransFusion-L > VoxelNeXt by ~3-4 mAP, matching the README). This is enough to release them for `E2.x` attack-side work; the final ±0.5 trainval-val authenticity check is a one-time job that fires the moment the full nuScenes is on disk.
- Google Drive is the only distribution channel for OpenPCDet's KITTI/nuScenes checkpoints. From this node it is unreachable, so every remaining checkpoint will need either (a) a community mirror, (b) `scp` upload from a host that can reach Drive, or (c) self-training.
- For Waymo, the OpenPCDet README explicitly says "We could not provide the above pretrained models due to Waymo Dataset License Agreement." That was the main reason the Waymo plan was abandoned in favor of nuScenes; see `E0.5` for the full decision record. The deferred `E4.5_deferred_waymo_mppnet.md` retains the Waymo / MPPNet hook for potential post-ICASSP future work.

## 8. Issues encountered & resolutions

- **Google Drive unreachable from autodl.** Symptom: `curl --connect-timeout 6 https://drive.google.com` returns `code=000`. Resolution for PointPillars: switched to the `gakkiri/simple-pointpillar` GitHub mirror; verified authenticity by AP round-trip in `E1.1`. Open for PV-RCNN and others.
- **`raw.githubusercontent.com` redirect.** First `curl -sI` returned 301; needed `-fL` to follow redirects. Resolved.
- **Mirror trust.** Risk: a community mirror could ship a poisoned checkpoint. Mitigation: every downloaded file must reproduce the official per-class AP in the matching `E1.x` baseline before being used downstream. PointPillars passed.
