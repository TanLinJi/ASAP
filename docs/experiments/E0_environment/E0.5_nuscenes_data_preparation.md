> **Scope decision (2026-05-21).** This file *supersedes* the previous `E0.5_waymo_data_preparation.md`. After the Waymo blocker analysis (3 upstream constraints; see the original Waymo file's §3.0), the user picked **option (C3-c): replace Waymo with nuScenes**. nuScenes is reachable from this autodl node (`curl -s -o /dev/null -w "%{http_code}" --connect-timeout 6 https://www.nuscenes.org` returns `200`; the CDN `d36yt3mvayqw5m.cloudfront.net` also returns `200`), the OpenPCDet model zoo *does* ship nuScenes pretrained checkpoints, and total raw data is ~360 GB (vs. 1.5 TB for Waymo). Downstream experiments `E1.3 / E1.4 / E4.3 / E4.4` have been retargeted accordingly.

## 1. Purpose / hypothesis

Download and pre-process the **nuScenes v1.0-trainval** LiDAR data so that `E1.3` (VoxelNeXt clean baseline), `E1.4` (TransFusion-Lidar clean baseline), `E2.x@nuScenes` (attacks), and `E4.3 / E4.4` (main results) can run inside the `asap` env with the official pretrained checkpoints from `E0.4`.

Success criteria:
1. `nuscenes_infos_10sweeps_train.pkl` and `nuscenes_infos_10sweeps_val.pkl` are generated under `data/nuscenes/v1.0-trainval/`, with the standard counts (700 train scenes / 150 val scenes; 6019 val samples).
2. `gt_database_10sweeps_withvelo/` is populated for ground-truth sampling augmentation (used only at training time; the gt-sampling step is therefore *optional* for our inference-only ASAP, but cheap to run).
3. A spot-check loads at least one nuScenes sample inside the `asap` env without error.

## 2. Dependencies

- `E0.2` (`asap` env).
- `E0.3` (OpenPCDet backend installed editable; provides the `pcdet.datasets.nuscenes` module).
- `nuscenes-devkit==1.0.5` installed into the `asap` env (per OpenPCDet's GETTING_STARTED).
- A nuScenes account (free; email-gated at <https://www.nuscenes.org/sign-up>); user-side action.
- Disk: ~360 GB raw + ~30 GB processed infos. Current free space on `/root/autodl-tmp`: 2.6 TB (per `df -h` 2026-05-20), so this fits.

## 4. Procedure

1. **User-side**: register a nuScenes account at <https://www.nuscenes.org/sign-up>, accept the license, copy the per-archive download URLs from <https://www.nuscenes.org/download> into a small text file (`scripts/nuscenes_urls.txt`).
2. **autodl-side**: from the URL list, `wget`/`curl` the **v1.0-trainval** archives:
   - 10 part-files of LiDAR/camera samples + sweeps (`v1.0-trainval01_blobs.tgz` … `v1.0-trainval10_blobs.tgz`),
   - 1 metadata archive (`v1.0-trainval_meta.tgz`),
   - the `nuScenes-map-expansion-v1.3.zip` for maps (only needed if `with_maps=True`, which is *not* required for our LiDAR-only detectors).
3. Extract the archives into `data/nuscenes/v1.0-trainval/` so that the layout in §3.2 holds.
4. Symlink `data/nuscenes` into `third_party/OpenPCDet/data/nuscenes` so the OpenPCDet entry-points see it under their expected path (analogous to the KITTI symlink in `E0.3`).
5. Install `nuscenes-devkit==1.0.5` into the `asap` env.
6. Run the OpenPCDet `create_nuscenes_infos` command from §3.3.
7. **Spot check** inside the `asap` env: load one sample via `nuscenes-devkit`, deserialize one `LIDAR_TOP` `.pcd.bin`, assert it returns a `(N, 5)` float32 array (x, y, z, intensity, ring).

## 5. Expected output

- The two `nuscenes_infos_10sweeps_{train,val}.pkl` files.
- A populated `gt_database_10sweeps_withvelo/` directory.
- Spot-check returning a non-empty `(N, 5)` point array for one frame from the val split.

## 7. Analysis

- nuScenes is meaningfully more attainable than Waymo from this autodl node: the CDN is directly reachable, the dataset is gated by registration only (not by a separate Google Cloud account), OpenPCDet ships pretrained checkpoints, and total raw size is ~25% of Waymo's.
- The trade-off vs Waymo: nuScenes uses a 32-beam, 360-degree, 20Hz Velodyne HDL-32E, qualitatively different from Waymo's 64-beam frontal layout. The paper's *cross-dataset* claim is therefore framed as "KITTI (64-beam frontal) + nuScenes (32-beam 360°)", which covers two distinct sensor configurations.
- The mini split (`v1.0-mini`, ~4 GB) is a useful smoke-test target before committing the full 360 GB transfer. We may run a one-time `v1.0-mini` smoke check before kicking off the full download to validate the `nuscenes-devkit` / OpenPCDet pipeline on this host.

## 8. Issues encountered & resolutions

### 8.1 `v1.0-mini` smoke (2026-05-21) — no blocker

- **Download.** No issues. The CloudFront host `d36yt3mvayqw5m.cloudfront.net` served the file directly with a *public* path (`/public/v1.0/v1.0-mini.tgz`); no signed URL or session cookie was needed. The nuScenes Download UI calls a JS click handler that hides this static URL behind a `href="#"` button, which is why right-click → *Copy link address* returned `https://www.nuscenes.org/download#`; the actual URL surfaces in `chrome://downloads/` once the click triggers the request.
- **Devkit dependencies.** `nuscenes-devkit==1.0.5` pulls in `jupyter / ipywidgets / matplotlib / motmetrics / pandas / scikit-learn` (the upstream package treats notebooks as a first-class use case). 50+ transitive packages, but all resolved through the configured Tsinghua PyPI mirror without conflict against the existing `asap` env.
- **Path resolution.** `pcdet/datasets/nuscenes/nuscenes_dataset.py:__main__` computes `data_path = ROOT_DIR / 'data' / 'nuscenes'`, i.e. `OpenPCDet/data/nuscenes`. The symlink `OpenPCDet/data/nuscenes -> /root/autodl-tmp/data/nuscenes` resolves this transparently, identical to the working KITTI layout.
- **`v1.0-mini` is not `v1.0-trainval`.** The script's default `--version v1.0-trainval` would fail on mini; passing `--version v1.0-mini` explicitly was required. OpenPCDet then auto-uses `mini_train` / `mini_val` splits from `nuscenes-devkit/utils/splits.py` (`8 + 2 = 10 scenes`).

### 8.2 Expected pitfalls for `v1.0-trainval`

Still applicable for the full download:

- **Per-archive size + URL nature.** The 10 `blobs.tgz` parts are each 26–39 GB. Contrary to the original assumption, the user-supplied URLs are **public** (split between `d36yt3mvayqw5m.cloudfront.net` and `motional-nuscenes.s3.amazonaws.com`, no `?Expires=&Signature=` query parameters), so they *do not* expire and can be resumed indefinitely. We still verify each tarball's MD5 against the nuScenes download page after the run finishes (recorded in §6.2 once available).
- **Symlink ordering with `gt_database_10sweeps_withvelo`.** OpenPCDet writes the gt-sampling database *under* `data/nuscenes/v1.0-trainval/`; if `data/nuscenes` is symlinked, the writes still resolve through the link (verified on mini).
- **`nuscenes-devkit` pin.** OpenPCDet expects exactly `1.0.5`; later devkit versions changed the `LidarPointCloud.load_pcd_bin` signature and break `create_nuscenes_infos`. (Confirmed working on mini.)
- **NumPy / devkit compatibility shim.** `nuscenes-devkit==1.0.5` uses deprecated `np.float` / `np.int`; the workaround patched into `pcdet/datasets/nuscenes/nuscenes_dataset.py` (4-line shim re-aliasing `np.float = float`, `np.int = int`) on 2026-05-21 — see `E1.3 §8` — must remain in place for the trainval evaluation too.
