## 1. Purpose / hypothesis

Reproduce the **official KITTI val 3D AP** of OpenPCDet PointPillars in our local environment, so that all downstream attack and defense numbers are evaluated against a trustworthy upper bound.

Success criterion: 3D AP per class (Car/Pedestrian/Cyclist, moderate difficulty) falls within ±0.5 absolute of the OpenPCDet model-zoo number.

## 2. Dependencies

- `E0.1` KITTI data on disk.
- `E0.2` `asap` env.
- `E0.3` OpenPCDet installed + KITTI infos generated.
- `E0.4` PointPillars checkpoint downloaded under `checkpoints/kitti/`.

## 3. Setup

### 3.1 Hardware & environment

- 1 GPU sufficient (PointPillars is light); 2 × T4 available on the dev node.
- `LD_LIBRARY_PATH` set per `E0.3`.

### 3.2 Data

- KITTI val split, 3769 frames.
- No attack applied.

### 3.3 Detector / config

- Config: `third_party/OpenPCDet/tools/cfgs/kitti_models/pointpillar.yaml`.
- Checkpoint: `checkpoints/kitti/pointpillar_7728.pth` (file name and SHA recorded in `E0.4`).
- Batch size: 4 (matches official eval).

### 3.4 Reproducible command (as actually executed 2026-05-20)

The command **must be launched from `third_party/OpenPCDet/tools/`** (not from the repo root) because the yaml config uses `_BASE_CONFIG_: cfgs/dataset_configs/kitti_dataset.yaml` which is resolved relative to the cwd. The command **must call the env interpreter directly** (not via `conda run`) because `conda run` buffers stdout/stderr and swallowed the libnvvm error in our first attempt (see `E0.2` §8).

```bash
cd /root/autodl-tmp/ASAP/third_party/OpenPCDet/tools
NVVM_ROOT=/root/miniconda3/envs/asap/lib/python3.9/site-packages/nvidia/cuda_nvcc/nvvm
env \
    LD_LIBRARY_PATH=/root/miniconda3/envs/asap/lib/python3.9/site-packages/torch/lib:/usr/local/cuda-12.4/lib64:$NVVM_ROOT/lib64 \
    NUMBAPRO_NVVM=$NVVM_ROOT/lib64/libnvvm.so \
    NUMBAPRO_LIBDEVICE=$NVVM_ROOT/libdevice \
    CUDA_HOME=/usr/local/cuda-12.4 \
    /root/miniconda3/envs/asap/bin/python -u test.py \
        --cfg_file cfgs/kitti_models/pointpillar.yaml \
        --ckpt /root/autodl-tmp/ASAP/checkpoints/kitti/pointpillar_7728.pth \
        --batch_size 4 \
        --extra_tag E1.1_clean \
    2>&1 | tee /root/autodl-tmp/ASAP/outputs/E1.1/run.log
```

## 4. Procedure

## 7. Analysis

- Two of three classes match the OpenPCDet README to two decimals; Cyclist deviates by 0.07 AP, which is well within both the success criterion (±0.5) and typical CUDA-non-determinism noise on KITTI.
- The matching numbers double as authenticity proof for the GitHub mirror used in `E0.4`: a poisoned checkpoint would almost certainly not reproduce three independent per-class APs to two decimals.
- Per-frame inference is **32 ms** on a single T4 (3769 frames in ~2 min forward time). This sets a reference for `E6.1`: any defense whose purification cost is above ~32 ms per frame doubles the end-to-end latency on this hardware.

## 8. Issues encountered & resolutions

- **First attempt: relative `_BASE_CONFIG_` path resolution.** Running `python tools/test.py --cfg_file tools/cfgs/kitti_models/pointpillar.yaml` from the repo root crashed with `FileNotFoundError: 'cfgs/dataset_configs/kitti_dataset.yaml'`. Cause: OpenPCDet resolves `_BASE_CONFIG_` relative to the *current working directory*, not relative to the cfg file. Fix: launch from `third_party/OpenPCDet/tools/` and pass `--cfg_file cfgs/kitti_models/pointpillar.yaml`.
- **Second attempt: `libNVVM cannot be found` during KITTI eval.** Cause: OpenPCDet's KITTI evaluation uses `@cuda.jit` (rotated IoU) which needs `libnvvm.so`; the system CUDA install does not ship it. Fix: `pip install nvidia-cuda-nvcc-cu12` + export `NUMBAPRO_NVVM`/`NUMBAPRO_LIBDEVICE`/`LD_LIBRARY_PATH` to point at the wheel's `nvvm/` directory. Both fixes are now recorded in `E0.2` §8.
- **Third attempt: `conda run -n asap` swallowed all stderr.** Cause: `conda run` buffers child output and only flushes on exit. Fix: call `/root/miniconda3/envs/asap/bin/python -u` directly, bypassing `conda run` entirely.
