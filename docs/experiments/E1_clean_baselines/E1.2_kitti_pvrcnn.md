## 1. Purpose / hypothesis

Same as `E1.1` but for **PV-RCNN**, a two-stage voxel-point detector. PV-RCNN is the second KITTI detector used to support the *detector-agnostic on KITTI* claim of milestone MS2 and Table 1's KITTI PV-RCNN row.

Success criterion: 3D AP per class within ±0.5 absolute of the OpenPCDet model-zoo number.

## 2. Dependencies

- `E0.1` KITTI data.
- `E0.2` `asap` env.
- `E0.3` OpenPCDet + infos.
- `E0.4` PV-RCNN checkpoint downloaded under `checkpoints/kitti/`.

### 3.3 Reproducible command (as actually executed 2026-05-21)

Uses the same `cd tools/` + libnvvm + direct-interpreter pattern as `E1.1` (rationale: see `E1.1` §8 / `E0.2` §8).

```bash
cd /root/autodl-tmp/ASAP/third_party/OpenPCDet/tools
NVVM_ROOT=/root/miniconda3/envs/asap/lib/python3.9/site-packages/nvidia/cuda_nvcc/nvvm
env \
    CUDA_VISIBLE_DEVICES=0 \
    LD_LIBRARY_PATH=/root/miniconda3/envs/asap/lib/python3.9/site-packages/torch/lib:/usr/local/cuda-12.4/lib64:$NVVM_ROOT/lib64 \
    NUMBAPRO_NVVM=$NVVM_ROOT/lib64/libnvvm.so \
    NUMBAPRO_LIBDEVICE=$NVVM_ROOT/libdevice \
    CUDA_HOME=/usr/local/cuda-12.4 \
    /root/miniconda3/envs/asap/bin/python -u test.py \
        --cfg_file cfgs/kitti_models/pv_rcnn.yaml \
        --batch_size 2 --workers 2 \
        --ckpt /root/autodl-tmp/ASAP/checkpoints/kitti/pv_rcnn_8369.pth \
        --extra_tag asap_e12_clean \
    2>&1 | tee /root/autodl-tmp/ASAP/outputs/E1.2/run.log
```

## 7. Analysis

### 7.1 Authenticity — bit-exact match against the checkpoint's encoded metric

OpenPCDet uses a `<model>_<XX><YY>.pth` naming convention where `XX.YY` is the Car-Moderate-3D-AP@R11 of that specific release (verified on `E1.1`: `pointpillar_7728.pth` → we got 77.28 to four decimals; verified again here: `pv_rcnn_8369.pth` → we got 83.6901, i.e. 83.69 to four decimals). For both KITTI checkpoints downloaded via separate paths (PointPillars from `gakkiri/simple-pointpillar` GitHub mirror; PV-RCNN from user `scp` upload of OpenPCDet's Google Drive artifact), the round-trip `download → torch.load → KITTI eval → metric matches the filename` is exact. Both checkpoints are therefore considered authentic, and the corresponding rows of paper Table 1 can be filled with full confidence.

### 7.2 Apparent gap vs current OpenPCDet README

The **current** OpenPCDet README's KITTI baseline table reports `Car/Ped/Cyc = 84.83 / 57.90 / 71.96` for PV-RCNN, which is ~1–3 points higher than our `83.69 / 54.84 / 69.48`. This is **not a discrepancy in our run** — it is because the README has been bumped to a newer / better-augmented PV-RCNN release (most likely `pv_rcnn_8462.pth` or later), while the `_8369.pth` artifact is the historical release that the user-supplied Google Drive link still points to. Our reproduction is faithful to the artifact we have. Should the paper later require the +1.0–3.0 AP improvement, we would need to obtain the newer ckpt or fine-tune; for now the historical `_8369` release is sufficient since (a) it is the canonical *clean* baseline against which our attacks are run, and (b) every attack/defense cell of paper Table 1 will use the **same** ckpt, so absolute clean numbers cancel out of the headline robustness deltas.

### 7.3 Cross-detector sanity check (vs PointPillars on KITTI val)

| Class · Mod 3D R11 | PointPillars (E1.1) | PV-RCNN (E1.2) | Δ |
|---------------------|--------------------:|---------------:|--:|
| Car                | 77.28 | **83.69** | +6.41 |
| Pedestrian         | 52.29 | **54.84** | +2.55 |
| Cyclist            | 62.61 | **69.48** | +6.87 |

PV-RCNN improves on every class as expected from the two-stage refinement, with the largest gains on Car (rigid, voxel-friendly) and Cyclist (small but rigid). Pedestrian gain is smallest, consistent with PV-RCNN's known limitation on highly-articulated targets where the second-stage point grid pooling has fewer reliable points to refine on.

### 7.4 Throughput

At 6.85 frame/s with `bs=2` on a T4 the full KITTI val takes ~9 min, vs ~2 min for PointPillars (32 frame/s, `bs=4`). PV-RCNN second-stage point ops are the dominant cost, exactly as predicted in `E0.4 §3.1`.
