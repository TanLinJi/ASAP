## 1. Purpose / hypothesis

Produce a detector-agnostic *geometric point-injection* attacked KITTI val set by inserting small point clusters around each annotated object. This produces the attacked set consumed by `E3.*` defenses and `E4.1`.

Important scope note: the current implementation is **not** a gradient-optimized Cao/Tu reproduction. It is a geometric injection variant designed to close the first ASAP attack-defense loop. If the paper needs a stronger detector-aware threat model, this E2.1 record must be extended before final submission.

Success criterion: against the *no-defense* baseline of the corresponding `E1.x` clean baseline, the injection attack reduces 3D AP by at least the threshold required to make a defense study meaningful (rule of thumb: ≥ 10 absolute AP drop on KITTI Car/Moderate).

## 2. Dependencies

- `E1.1` clean PointPillars baseline.
- `E0.1` KITTI val data and `E0.3` OpenPCDet info files.

## 3. Setup

### 3.1 Hardware & environment

- Same `asap` env as `E0.2`.
- Same machine class as the corresponding `E1.x` (so that detector gradients match).

### 3.2 Attack parameters

- Per-target injected point budget: `k_inj = 50`.
- Spatial expansion around each GT box: `r_inj = 0.5 m`.
- Random seed: `42`.
- Frames: full KITTI val, 3769 scans.
- Total targeted objects: 17558.
- Total injected points: 877900.

### 3.3 Output layout

```text
outputs/attacks/kitti/E2.1_injection/
├── velodyne_attacked/
│   └── 000000.bin, 000001.bin, ...
├── attack_meta.jsonl     # per-frame budget, seed, injected points
└── attack_log.txt
```

### 3.4 Reproducible command

```bash
PYTHONPATH=src /root/miniconda3/envs/asap/bin/python -m asap.attacks.point_injection \
    --info_pkl data/kitti/kitti_infos_val.pkl \
    --velodyne_dir data/kitti/training/velodyne \
    --out_dir outputs/attacks/kitti/E2.1_injection \
    --k_inj 50 --r_inj 0.5 --seed 42
```

### 3.5 nuScenes keyframe-only setup

The nuScenes attack uses the same geometric injection budget but only edits the current keyframe file referenced by `info["lidar_path"]`. Historical sweeps remain clean under OpenPCDet's default `MAX_SWEEPS=10` configuration. This is the low-cost first nuScenes robustness loop and must be reported as keyframe-only.

- Dataset/split: nuScenes `v1.0-trainval` val, 6019 keyframes.
- Info file: `data/nuscenes/v1.0-trainval/nuscenes_infos_10sweeps_val.pkl`.
- Per-target injected point budget: `k_inj = 50`.
- Spatial expansion around each GT box: `r_inj = 0.5 m`.
- Random seed: `42`.
- Total targeted objects: 158253.
- Total injected points: 7912650.
- Output: `outputs/attacks/nuscenes_keyframe/E2.1_injection/samples/LIDAR_TOP/`.

Reproducible command:

```bash
bash scripts/run_nuscenes_keyframe_attacks.sh
```

## 4. Procedure

1. Run the geometric injection script on all KITTI val frames.
2. Evaluate the no-defense PointPillars detector on the attacked set using `scripts/eval_attacked_kitti.sh`.
3. Persist 3D AP under attack and ASR to §6.
4. Feed the attacked set into SOR/ROR and ASAP for `E4.1`.

## 5. Expected output

- Attacked LiDAR bins under `outputs/attacks/.../velodyne_attacked/`.
- A per-detector "no-defense under attack" AP / ASR row, which is the *No defense* column of every `E4.x` *Injection* row.

## 7. Analysis

The geometric injection attack is meaningful for the first PointPillars robustness loop: Car/Mod AP_R40 drops from 78.40 to 60.10. The nuScenes keyframe-only variant is also clearly strong on VoxelNeXt: mAP drops from 60.52 to 21.97 and NDS from 66.64 to 41.87. Its limitation is threat-model strength: it inserts points around GT boxes without optimizing detector loss, so paper text must call it a geometric injection attack rather than a gradient-based physical spoofing reproduction.

## 8. Issues encountered & resolutions

- The original E2.1 skeleton described a detector-gradient attack. The implemented protocol is geometric; this was made explicit here to avoid overclaiming in the paper.
