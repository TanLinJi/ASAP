## 1. Purpose / hypothesis

Apply *Statistical Outlier Removal* (SOR) to the attacked val sets produced by `E2.x` and feed the cleaned point clouds into the corresponding victim detector. SOR is the closest classical, training-free, detector-agnostic analog of ASAP and isolates the value of ASAP's diffusion step.

Success criterion: recovers some detection accuracy under attack but, per the M2 motivation in `paper/03_method.md`, also damages clean accuracy because it acts globally on the scan.

## 2. Dependencies

- The corresponding `E1.x` clean baseline (for *clean recovery* sanity check).
- The corresponding `E2.x` attacked set.

## 3. Setup

### 3.1 Defense parameters

- $k$-NN size: `k_sor` (default: 20).
- Std multiplier: `std_mul` (default: 1.0).
- These follow PCL conventions and are recorded inside the implementation.

### 3.2 Output layout

```text
outputs/defenses/kitti/E3.1_sor/
├── E2.1_injection/velodyne_defended/
├── E2.2_perturbation/velodyne_defended/
└── E2.3_dropping/velodyne_defended/
```

### 3.3 Reproducible command

```bash
PYTHONPATH=src /root/miniconda3/envs/asap/bin/python -m asap.defenses.statistical_filters \
    --method sor \
    --input_dir outputs/attacks/kitti/E2.1_injection/velodyne_attacked \
    --out_dir outputs/defenses/kitti/E3.1_sor/E2.1_injection/velodyne_defended \
    --k_neighbors 20 --alpha 1.0
```

## 4. Procedure

1. Run `src/asap/defenses/statistical_filters.py --method sor` on every KITTI/PointPillars attacked val set.
2. Save defended bins under `velodyne_defended/`.
3. Evaluate the victim detector on the purified val set using `tools/test.py` with the purified velodyne folder mounted.
4. Record AP / ASR for the `E4.x` *SOR* row.

## 5. Expected output

- Purified LiDAR bins.
- AP / ASR for every (detector, attack) cell.

## 6. Actual results

Clean reference (`E1.1`): PointPillars KITTI Car/Moderate 3D AP_R40 = 78.40; mAP_R40 Mod = 64.21.

| Attack | Car/Mod 3D AP_R40 | ASR vs clean Car | mAP_R40 Mod |
|--------|------------------:|-----------------:|------------:|
| E2.1 Injection | 58.00 | 26.0% | 43.77 |
| E2.2 Perturbation | 34.12 | 56.5% | 14.99 |
| E2.3 Dropping | 40.16 | 48.8% | 28.44 |

Raw summary source: `outputs/asap_vpsde/kitti_pointpillars_eval_summary.json`, entries `E2.1 SOR`, `E2.2 SOR`, `E2.3 SOR`.

## 7. Analysis

SOR is harmful on perturbation and dropping in the current setting. It removes or distorts valid sparse object evidence, especially for already damaged point clouds. It only improves mAP relative to no-defense for injection because Pedestrian/Cyclist recover somewhat, but it still lowers Car AP versus no-defense.

## 8. Issues encountered & resolutions

- The output directory uses `velodyne_defended/`, while the original skeleton used `velodyne_purified/`. `scripts/eval_attacked_kitti.sh` supports both names.

## 9. Next actions

- Feed purified evaluations into `E4.x` SOR rows.
- Keep SOR as a classical baseline, not as a strong final defense.
