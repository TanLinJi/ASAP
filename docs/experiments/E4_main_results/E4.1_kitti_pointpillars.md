## 1. Purpose / hypothesis

Produce the **first end-to-end ASAP result** by running each defense in `{No-defense, SOR (E3.1), ROR (E3.2), ASAP variants}` against each attack in `{Injection (E2.1), Perturbation (E2.2), Dropping (E2.3)}` on KITTI val with PointPillars. This experiment is the central MS1 sanity check for the M1->M2->M3 implementation.

Hypothesis for the final method: **ASAP with selective VP-SDE purification should improve attacked detection without detector retraining**. The historical `DropPurifier`, local-mean fallback, and hybrid rows are treated as implementation milestones and ablations. The current Track A candidate is attack-conditional: b075-ifilter for Injection, b075 for Perturbation and Dropping.

## 4. Procedure

1. Generate purified scans for every attack with `python -m asap.pipeline`.
2. Calibrate M2 per attack with Receiver Operating Characteristic (ROC) + Youden-$J$ on 20 paired calibration frames.
3. Evaluate PointPillars on each purified set.
4. Fill the 3 × 4 grid of (attack, defense) cells in §6.
5. Compute ASR per cell as `1 - AP_attacked_defended / AP_clean_E1.1`.

## 5. Expected output

- A complete 3 × 4 result grid (3 attacks × 4 defenses) reported as `(AP, ASR)` per cell.
- Saved `result.pkl` per cell and a consolidated summary CSV under §6.

## 7. Analysis

### 7.1 ASAP-drop prototype (point deletion)

- **Injection:** ROR best. ASAP-drop close to no-defense but below ROR because dropping flagged inner points removes some legitimate object support together with injected clusters.
- **Perturbation:** SOR and ROR severely hurt performance; naive outlier removal removes valid object points under sparse perturbations. ASAP-drop is less destructive than SOR/ROR but still below no-defense (edit rate 21.93%).
- **Dropping:** No-defense remains best because the attack already removed points; additional point removal compounds the damage. ASAP-drop is better than SOR/ROR but still below no-defense.
- **Diagnosis:** M1 and M2 are functional, but M3 cannot be pure deletion. Replacing it with non-destructive editing is the right move.

### 7.2 ASAP-vpsde (local-mean fallback)

Switching M3 from deletion to local-mean smoothing (8-NN attraction toward non-flagged neighbors) preserves point count and gives the **first ASAP win**:

- **Perturbation (E2.2):** Car AP recovers from 56.54 → 60.10 — **exceeding the no-defense baseline**. ASR drops 27.9% → 23.3%. mAP jumps 27.32 → 32.79. This validates the central ASAP hypothesis: selective repair, not deletion, restores detection performance against geometric perturbations.
- **Injection (E2.1):** Matches no-defense (60.18 vs 60.10) but does not beat ROR (66.07). Local-mean cannot remove tight injected clusters because the 8 nearest non-flagged neighbors of an injected point are often other injected points or empty space; the cluster collapses rather than dissipates.
- **Dropping (E2.3):** Slightly above ASAP-drop (66.68 vs 65.89) but still below no-defense (71.22). Local-mean cannot regenerate points the attacker removed; it can only edit existing points. Pedestrian/Cyclist AP drop suggests false positive flags hurt sparse classes.
- **Headline:** local-mean fallback alone is enough to flip ASAP from net-negative to net-positive on the hardest attack family. A trained VP-SDE score network should further improve injection and dropping via stronger manifold projection and (optionally) point regeneration.

### 7.3 ASAP-hybrid (drop + smooth ablation)

The hybrid M3 was added to test the §7.2 conjecture that anisotropy-gated drops on top of local-mean smoothing should help **Injection** without sacrificing Perturbation. Numerical outcome:

- **Injection (E2.1):** Car AP 59.80 (vs vpsde 60.18, no-defense 60.10); mAP 42.44 (vs vpsde 41.71, no-defense 38.73). The added **isolation-radius drop branch** (radius 0.30 m, min-neighbors 3) removes some sparse off-surface injection points and lifts mAP by +0.73 vs vpsde, but Car AP drops 0.38 because the same rule occasionally trims a few legitimate sparse Car points. Hybrid still loses to ROR (66.07 / 51.30) on this attack: ROR's pure-distance criterion is intrinsically well matched to off-surface injected points, while hybrid only triggers inside M2-flagged SPUs.
- **Perturbation (E2.2):** Car AP 58.41 (vs vpsde **60.10**, no-defense 56.54); mAP 30.78 (vs vpsde **32.79**). Hybrid **regresses 1.69 AP** vs the vp_sde local-mean win. Diagnosis: under perturbation many genuine object points end up sparse (≤3 neighbors at 0.30 m) and get dropped by the isolation branch, whereas vp_sde would have pulled them back onto the local manifold. The cluster-drop branch (anisotropy ≥0.97, top 10% score) by itself is benign here (only ~1% of flagged SPUs); the isolation branch is the one that hurts.
- **Dropping (E2.3):** Car AP 67.67 (vs vpsde 66.68, no-defense 71.22); mAP 32.86 (vs vpsde 32.65). Hybrid is the **best ASAP variant on this attack** by a small margin (+0.99 Car, +0.21 mAP) because removing already-isolated points and smoothing the rest beats smoothing alone, but still trails no-defense.
- **Headline:** hybrid is **not strictly better** than vp_sde local-mean. It is a useful ablation that shows two distinct sub-rules with opposite effects: (a) anisotropy-gated cluster drop is **safe** (≤1% of flagged SPUs and no measurable downside) and should stay; (b) global isolation-radius drop is **too aggressive** for Perturbation. The right next step is to keep the cluster-drop branch but make the isolation drop attack-aware (e.g. only when M2 ROC indicates an injection-shaped distribution, or per-SPU sparsity-adapted radius).
- **Cluster-only ablation (`hybrid-co`):** to verify the diagnosis above we re-ran hybrid with `--hybrid_isolation_radius 0 --hybrid_min_neighbors 0` (cluster-drop branch only). Result:
  - **E2.1:** 60.18 / 41.71 — *identical* to vp_sde local-mean. The cluster gate (anisotropy ≥0.97 AND top-10% score AND ≥2τ) does not trigger on any SPU on injection (single-frame check: 0 drop SPUs out of 1707 flagged), so hybrid-co collapses to vp_sde here.
  - **E2.2:** 59.85 / 32.62 — recovers **+1.44 Car AP / +1.84 mAP** over hybrid (58.41 / 30.78), almost matching vp_sde (60.10 / 32.79). The remaining 0.25 AP gap vs vp_sde is from the 78 cluster-drop SPUs (~1.0% of flagged) that delete genuine sparse points. This **isolates the Perturbation regression to the isolation-radius drop branch**.
  - **E2.3:** 67.63 / 32.85 — within ±0.04 of full hybrid (67.67 / 32.86), and +0.95 / +0.20 above vp_sde. Cluster drop is the useful piece on Dropping; isolation drop adds nothing (most points already have plenty of neighbors). This **isolates the small Dropping gain to the cluster-drop branch**.

  Combined: the cluster-drop branch is essentially **free** (no measurable cost on any attack and a small win on Dropping); the isolation-radius branch is **attack-specific** (small mAP gain on Injection, large AP loss on Perturbation). Recommendation: keep cluster-drop on by default, gate isolation-drop on an attack-prior flag in M2.

- **Attack-conditional ablation (`hybrid-cond`):** `ScorerConfig.attack_kind` is inferred during calibration and passed into `PurifierConfig`; existing scorer JSONs were patched with `{injection, perturbation, dropping}`. `HybridPurifier` now enables the isolation-radius branch only for `attack_kind == "injection"` and disables it for Perturbation / Dropping. Result:
  - **E2.1:** 59.80 / 42.44 — identical to full hybrid, as expected, because injection keeps the isolation branch enabled.
  - **E2.2:** 59.85 / 32.62 — identical to cluster-only and recovers most of the full-hybrid regression, confirming that attack-conditioning removes the harmful perturbation isolation drops.
  - **E2.3:** 67.63 / 32.85 — identical to cluster-only and preserves the small dropping gain over vp_sde.

  Combined: `hybrid-cond` is the best single hybrid policy among the ablations, because it keeps the injection mAP gain of full hybrid while preserving the perturbation/dropping behavior of cluster-only. It still does not beat `ASAP-vpsde` on Perturbation Car AP (59.85 vs 60.10) and does not beat ROR on Injection Car AP (59.80 vs 66.07), so it should be reported as an ablation rather than the final ASAP row.

### 7.4 Track A score-net v1

The first learned score-net row is a useful Track A control point, and the anchor follow-up gives the first learned-M3 win over local-mean:

- **Pure score-net v1:** E2.2 Car AP improves no-defense by +1.84 AP (56.54 -> 58.38), and mAP improves by +2.09 (27.32 -> 29.41), but it underperforms local-mean by -1.72 Car AP and -3.38 mAP. The largest loss is on sparse classes (Pedestrian Mod AP 2.10, Cyclist Mod AP 27.76).
- **Score-net + local anchor (`score_anchor_blend=0.75`):** E2.2 Car AP reaches **61.04**, improving no-defense by +4.50 AP and local-mean by +0.94 AP. mAP reaches **34.69**, improving no-defense by +7.37 and local-mean by +1.90. Increasing the same branch to `t_star=0.08` gives the current best E2.2 row, **61.26 / 34.76**, while also improving PV-RCNN. On E2.3 Dropping, the original b075 branch reaches **68.49** Car AP, improving local-mean by +1.81 AP and hybrid-cond by +0.86 AP, but still trails the no-defense attacked scan (71.22). On E2.1 Injection, it reaches **59.97** Car AP and **39.63** mAP, so it does not beat local-mean, hybrid-cond, or ROR.
- **Score-net + local anchor + Injection filter (`score_injection_filter_radius=0.4`, `min_neighbors=5`):** E2.1 Car AP reaches **65.71**, improving raw b075 by +5.74 AP and local-mean by +5.53 AP. Its mAP reaches **52.18**, improving raw b075 by +12.55 and exceeding ROR mAP by +0.88. Car AP is still 0.36 below ROR (66.07), so the branch fixes the mAP failure and nearly closes the Car gap.
- **Interpretation:** the learned score direction is useful when constrained by a stable local-manifold anchor. Pure score-net is too weak or unstable for sparse classes, while the anchor preserves local structure and lets the score-net add a detector-useful correction.
- **Decision:** use attack-conditional learned M3 as the KITTI candidate: b075-ifilter for Injection, b075 with `t_star=0.08` for Perturbation, and skip M3 for Dropping in the cross-detector policy. The non-injection smoke confirms the Injection filter is disabled by `attack_kind` on E2.2/E2.3. E4.2 later confirms the Injection branch transfers to PV-RCNN but exposes a Dropping regression, so the cross-detector revised policy skips M3 for Dropping.

### 7.5 Fixed-SPU all-unit diffusion proxy

To test whether ASAP's gain comes merely from applying a learned local denoiser everywhere, we ran an internal SPD-style proxy on E2.2 Perturbation. This is not an official LiDAR-SPD reproduction. It uses fixed-radius spherical units (`r1=0.40 m`, `r2=0.67*r1`, `eta=0.40 m`), disables M2 selection with `tau=-1.0`, and reuses the same Track A score-net checkpoint and `score_anchor_blend=0.75`.

- Full KITTI val purification completed for 3769/3769 frames.
- PointPillars result: **57.16** Car/Moderate AP_R40 and **30.35** cross-class mAP.
- Selection/cost profile: **100.00%** SPUs flagged, **97.14%** SPUs enter score-net, and **77.86%** input points are edited.
- Comparison: it improves over no-defense mAP (30.35 vs 27.32) but remains clearly below ASAP Track A (61.04 / 34.69). This supports the claim that adaptive SPU construction and anomaly-guided selective purification are not cosmetic.

### 7.6 Adaptive-SPU all-unit ablation

P2 keeps ASAP's normal adaptive SPU construction but disables M2 with `tau=-1.0`. This isolates the value of anomaly-guided selection from the value of adaptive local neighborhoods.

- Full KITTI val purification completed for 3769/3769 frames.
- PointPillars result: **38.62** Car/Moderate AP_R40 and **17.88** cross-class mAP.
- Selection/cost profile: **100.00%** SPUs flagged, **95.92%** SPUs enter score-net, and **70.98%** input points are edited.
- Comparison: adaptive all-unit purification is worse than no defense (56.54 / 27.32), fixed-SPU all-unit proxy (57.16 / 30.35), and ASAP Track A (61.04 / 34.69). This makes M2 a central structure-preservation component rather than a mere acceleration gate.

### 7.7 Failure modes still open

- **Injection:** b075-ifilter shows that score-net+anchor plus a radius-neighbor removal branch is the right direction: mAP now exceeds ROR, but Car AP is still 0.36 below ROR. The remaining risk is whether the fixed `0.4 m / 5 neighbors` rule stays benign across detectors and datasets.
- **Dropping:** score-net+anchor improves the ASAP variants (68.49 vs 66.68 local-mean and 67.63 hybrid-cond), but it still cannot restore the no-defense attacked baseline (71.22). A final method that claims dropping robustness needs explicit point regeneration or a density-drop-specific reverse process.
- **Pedestrian / Cyclist:** M2 calibration is currently driven by Car-dominated frames; sparse-class points get flagged disproportionately. Need class-aware or sparsity-aware threshold per SPU radius band.
- **Hybrid isolation drop:** now attack-conditioned in `hybrid-cond`, which fixes the Perturbation regression relative to full hybrid but still does not beat vp_sde on Perturbation Car AP.

## 8. Issues encountered & resolutions

- `python -m asap.pipeline` initially failed because `src/asap/pipeline.py` was shadowed by the existing empty `src/asap/pipeline/` package. Resolution: moved implementation into `src/asap/pipeline/__init__.py` and added `src/asap/pipeline/__main__.py`.
- Batch purification was too slow in serial. Resolution: added multiprocessing (`--workers 16`), reducing runtime to roughly 126--136 ms/frame after calibration.
- Dropping-attack calibration initially failed because the first calibration logic only detected added or perturbed points. Resolution: added density-drop detection by comparing inner-ball point counts between clean and attacked clouds.
- `eval_attacked_kitti.sh` initially ignored `velodyne_purified/`. Resolution: added support for `velodyne_purified` alongside `velodyne_attacked` and `velodyne_defended`.
