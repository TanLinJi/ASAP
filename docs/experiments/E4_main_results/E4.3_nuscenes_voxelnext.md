## 1. Purpose / hypothesis

Mirror of `E4.1` (KITTI / PointPillars) on **nuScenes val + VoxelNeXt**, the strongest fully-sparse voxel detector with a publicly downloadable checkpoint. This experiment is one of the two central evidence rows for *detector-agnostic across recent SOTA + cross-dataset* in the abstract.

## 2. Dependencies

- `E0.5` nuScenes data preparation.
- `E0.4` row for nuScenes VoxelNeXt checkpoint.
- `E1.3` clean baseline (also acts as the `Clean (ref)` column here): mAP **60.52**, NDS **66.64**.
- `E2.x@nuScenes`: done as a detector-agnostic **keyframe-only** attack set under `outputs/attacks/nuscenes_keyframe/`.
- `E3.1` SOR and `E3.3` Uniform SPU diffusion baselines applied to the nuScenes attacked sets.

## 3. Setup

Same structure as `E4.1` §3, with:

- Dataset: nuScenes val (6019 samples).
- Detector: `cbgs_voxel0075_voxelnext.yaml` + the checkpoint from `E0.4`.
- Headline metric: nuScenes-native **mAP** and **NDS** (the nuScenes Detection Score = 0.5 × mAP + 0.5 × mean of normalized true-positive errors over translation, scale, orientation, velocity, attributes).
- Current attack scope: keyframe-only. The edited files replace `samples/LIDAR_TOP`; historical sweeps are still loaded from the clean `sweeps/` tree because the OpenPCDet config uses `MAX_SWEEPS=10`.

## 4. Procedure

Same procedure as `E4.1`, swapping dataset and detector. Specifically:

1. For each attack family `A in {injection, perturbation, dropping}`, generate the keyframe-only attacked nuScenes-val set with the unified attack budget from `E2.A` and save the edited `.pcd.bin`s under `outputs/attacks/nuscenes_keyframe/<E2.A>/samples/LIDAR_TOP/`.
2. Temporarily swap `data/nuscenes/v1.0-trainval/samples/LIDAR_TOP` to each attacked `samples/LIDAR_TOP` using `scripts/eval_attacked_nuscenes.sh`; the script uses a file lock and `trap` restore.
3. For each defense `D in {none, SOR/ROR or equivalent classical baseline, ASAP (ours)}`, run VoxelNeXt eval and record mAP / NDS / ASR.
4. ASR = 1 - (mAP-under-attack / mAP-clean) using the VoxelNeXt `Clean (ref)` from `E1.3`.

## 7. Analysis

Decision gate status: **passed for Injection**, **passed for revised Perturbation**, and **failed for Dropping** under keyframe-only budgets. E2.1 drops VoxelNeXt from 60.52/66.64 mAP/NDS to 21.97/41.87, mAP ASR 63.7%. Original E2.2 (`epsilon=0.3`) drops to 51.87/59.95, mAP ASR 14.3%, so it is only light-to-moderate. The revised budget (`epsilon=0.5`) drops to 40.27/51.46, mAP ASR 33.5%, which is strong enough to use as the accepted nuScenes Perturbation setting. E2.3 (`drop_ratio=0.5`) only drops to 58.91/65.76, mAP ASR 2.7%; even the upper-bound keyframe-only `drop_ratio=1.0` candidate only drops to 55.58/63.91, mAP ASR 8.2%. Dropping therefore remains too weak for a main nuScenes robustness claim unless the protocol becomes sweep-aware or saliency-aware.

SOR/ROR correction: ROR is a strong non-ASAP baseline on both accepted attacks. It reduces VoxelNeXt Injection ASR from 63.7% to 11.9%, and Perturbation ASR from 33.5% to 15.1%. This means the paper cannot claim easy dominance on nuScenes until ASAP rows beat or are honestly positioned against ROR.

ASAP-v1 outcome: the nuScenes Track A assets are valid but mixed. On Injection, ASAP-v1 recovers to 52.45/62.18, close to ROR's 53.29/62.66 but still behind by 0.84 mAP and 0.48 NDS. On Perturbation, ASAP-v1 reaches only 41.32/52.74, barely above no-defense 40.27/51.46 and far behind ROR 51.36/60.40. Meta statistics explain the split: Injection enables the post score-net radius filter and removes an average 17.8% of points, which approximates ROR-like outlier cleanup; Perturbation preserves point count and edits about 1.5k points per frame, but this score-net shift is not enough to undo the `epsilon=0.5` coordinate attack under the ten-sweep detector.

Plan correction from this result: do not run the TransFusion-Lidar ASAP full matrix blindly. First test a small perturbation-focused diagnostic, such as higher score-anchor blend / local-mean fallback or an ROR+ASAP hybrid, on VoxelNeXt. If the perturbation row remains near no-defense, position nuScenes ASAP-v1 as competitive on Injection only and keep ROR as the strongest accepted nuScenes baseline.

Perturbation pfilter diagnostic: the radius-filter cascade for `perturbation` is valid and changes the decision. The successful OpenPCDet run is `log_eval_20260531-183502.txt`, which ends with `Evaluation done`; `metrics_summary.json` was written at 2026-05-31 18:50 and reports mAP **52.27**, NDS **61.23**, mAP ASR **13.6%**. The earlier `asap_nusc_pfilter_voxelnext_20260531_162416.log` contains a failed eval caused by missing swapped LIDAR files, but the later retry under the same OpenPCDet tag completed successfully. The purified output directory is complete for 6019 validation samples and has no broken symlinks. Meta statistics show 6019 metadata rows, every frame edited, `score_filter_attack_kinds=['injection', 'perturbation']`, and **34,759,558** total radius-filter drops, averaging **5775** points/frame or **16.63%** of all input points. This explains the large gain over ASAP-v1: pfilter improves Perturbation from 41.32/52.74 to 52.27/61.23, beating ROR by +0.91 mAP and +0.83 NDS. The same pfilter output also improves TransFusion-Lidar Perturbation to 54.40/61.98 in `E4.4`, beating TransFusion ROR by +0.89 mAP and +0.75 NDS. The interpretation must remain honest: the improvement is not evidence that the learned score-net alone solves coordinate perturbation; it shows that the learned score-net becomes effective when paired with a ROR-like local support filter.

## 8. Issues encountered & resolutions

- nuScenes eval requires temporarily replacing `samples/LIDAR_TOP`. Added `scripts/eval_attacked_nuscenes.sh` with a file lock and `trap` restore to avoid leaving the clean data tree swapped after errors or SSH disconnects.
- Long eval ran under tmux and used `NUM_GPUS=2` distributed OpenPCDet eval where supported.
- E2.1 Injection produces many more post-filter predictions than clean (580920 vs 483902), so wall-clock is slower than the clean VoxelNeXt baseline; this is expected for the injected-point attack.

## 9. Next actions

- Keep the paper wording aligned with the final table: Injection is near-ROR but not dominant; Perturbation uses the explicitly labeled **ASAP-pfilter** cascade.
- Do not spend more GPU time on nuScenes Dropping unless a sweep-aware or saliency-aware attack protocol is implemented.
- Prioritize manuscript consistency and reviewer-risk cleanup over new large experiment matrices.
