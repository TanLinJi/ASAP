## 1. Purpose / hypothesis

Mirror of `E4.3` with **TransFusion-Lidar** (sparse 3D backbone + transformer query head) replacing VoxelNeXt. Provides a second nuScenes data point on a different head family, completing the four-architecture coverage that supports the *detector-agnostic* claim:

| Slot   | Dataset  | Detector family                          | Experiment |
|--------|----------|------------------------------------------|------------|
| Slot 1 | KITTI    | Pillar-based one-stage                   | `E4.1`     |
| Slot 2 | KITTI    | Voxel-point two-stage                    | `E4.2`     |
| Slot 3 | nuScenes | Fully sparse voxel CNN, anchor-free      | `E4.3`     |
| Slot 4 | nuScenes | Sparse voxel + transformer query head    | `E4.4` (this experiment) |

## 4. Procedure

Same procedure as `E4.3`, reusing the attacked nuScenes-val sets produced by `E2.x@nuScenes` so that *every defense column in this row sees the same attacked inputs as the corresponding column of `E4.3`*. This is the cleanest way to isolate the detector-axis effect.

Current gate outcome from `E4.3`: Injection is strong, revised Perturbation (`epsilon=0.5`) is strong enough for transfer evaluation, and Dropping remains too weak even at `drop_ratio=1.0`. Launch TransFusion-Lidar no-defense only on the accepted nuScenes attacks:

```bash

    bash scripts/eval_nuscenes_accepted_no_defense.sh
```

Target parser output: `outputs/attacks/nuscenes_keyframe_budget_gate/nuscenes_transfusion_lidar_accepted_no_defense_eval_summary.json`.

## 6. Actual results

Clean reference: mAP **64.57**, NDS **69.43** (`E1.4`). Accepted no-defense rows are parsed in `outputs/attacks/nuscenes_keyframe_budget_gate/nuscenes_transfusion_lidar_accepted_no_defense_eval_summary.json`; accepted SOR/ROR and Injection ASAP-v1 defense rows are parsed in `outputs/defenses/nuscenes_keyframe_accepted/nuscenes_transfusion_lidar_accepted_defenses_eval_summary.json`. The perturbation pfilter transfer row is parsed in `outputs/defenses/nuscenes_keyframe_accepted_asap_pfilter/nuscenes_transfusion_lidar_pfilter_eval_summary.json`. The accepted nuScenes transfer set is Injection original budget and Perturbation `epsilon=0.5`. Dropping remains paused because VoxelNeXt shows only 8.2% mAP ASR even at keyframe-only `drop_ratio=1.0`.

Cell format: `mAP / NDS / ASR`.

## 7. Analysis

TransFusion-Lidar confirms that the accepted nuScenes attacks transfer beyond VoxelNeXt: Injection drops mAP/NDS from 64.57/69.43 to 19.13/39.45, mAP ASR 70.4%, and revised Perturbation drops to 43.02/52.99, mAP ASR 33.4%. This supports a detector-transfer attack-strength claim for Injection and revised Perturbation only. Dropping should not be used in the TransFusion no-defense gate unless the protocol is upgraded beyond keyframe-only random object-point removal.

The SOR/ROR defense pass changes the nuScenes baseline landscape. ROR is the strongest non-ASAP baseline in both accepted rows, reducing Injection ASR to 11.3% and Perturbation ASR to 17.1%. SOR gives only partial recovery and can lag no-defense under perturbation-like shifts.

The Injection ASAP-v1 row is competitive but not dominant: it recovers to **56.74/64.72**, only 0.55 mAP and 0.32 NDS below ROR. This is useful evidence for detector transfer but should be phrased as near-parity with a strong classical support filter, not as superiority.

The perturbation pfilter transfer check is positive. Reusing the same ASAP-pfilter output from `E4.3` and evaluating it with TransFusion-Lidar gives mAP/NDS **54.40/61.98**, mAP ASR **15.75%**, and NDS ASR **10.73%**. This beats the TransFusion ROR perturbation row by +0.89 mAP and +0.75 NDS. Together with VoxelNeXt's 52.27/61.23 result, this supports a revised nuScenes Perturbation policy, but the policy must be named honestly as a score-net + radius-filter cascade rather than pure ASAP-v1.

- Perturbation pfilter transfer check executed in tmux session `asap_nusc_pfilter_transfusion_20260531_191355`; it reused the existing 6019-frame pfilter output, completed successfully, and restored clean `samples/LIDAR_TOP`.

## 9. Next actions

- Use Injection ASAP-v1 and Perturbation ASAP-pfilter in the paper table, with explicit labels.
- Emphasize that ROR remains marginally stronger on Injection, while ASAP-pfilter is stronger on Perturbation across both nuScenes detectors.
- Keep nuScenes Dropping paused unless a stronger sweep-aware/saliency-aware dropping protocol is implemented.
