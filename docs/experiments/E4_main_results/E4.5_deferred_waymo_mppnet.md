## 1. Why this experiment is deferred

Following the user decision on 2026-05-21 to swap **Waymo → nuScenes** (documented in `E0.5` §3.0), three independent constraints rule MPPNet out of the ICASSP scope:

1. **No nuScenes counterpart.** OpenPCDet ships MPPNet only for Waymo (`third_party/OpenPCDet/docs/guidelines_of_approaches/mppnet.md`); there is no `tools/cfgs/nuscenes_models/mppnet*.yaml`. So MPPNet cannot move to the new dataset without an upstream port.
2. **Waymo data + checkpoint unreachable.** Per `E0.5` §3.0, raw Waymo tfrecords require a Google account, a license click-through, and `gsutil` access to GCS, all of which are blocked from this autodl node. OpenPCDet additionally does *not* distribute Waymo pretrained checkpoints (`third_party/OpenPCDet/README.md` line 209), so MPPNet-Waymo would require ~3-4 days of single-T4 self-training even after the data is on disk.
3. **Multi-frame attack semantics are not yet defined in `E2.*`.** MPPNet consumes a temporal stack of frames; the canonical *point-injection / perturbation / dropping* attacks in `E2.1`–`E2.3` are defined per single scan. Extending them to multi-frame inputs is a non-trivial design decision that would need its own ablation, which is past the ICASSP page budget.

## 2. Re-activation criteria

This experiment can be moved back to `pending` if **all three** of the following become true:

- An OpenPCDet-compatible MPPNet checkpoint is available *and* reachable.
- The attack family in `E2.*` is extended with a multi-frame spec, with a clear definition of how the per-frame budget aggregates across the temporal window.
- The paper budget allows a Waymo row to coexist with the four nuScenes / KITTI rows already planned in `E4.1`-`E4.4`.
