## 1. Purpose / hypothesis

This focused sweep tests whether stricter M2 selection improves KITTI PointPillars Perturbation by reducing over-purification. The null outcome is that higher thresholds reduce cross-class mAP, in which case the ROC-calibrated Track A threshold should remain unchanged.

## 2. Dependencies

- `E1.1` KITTI PointPillars clean baseline.
- `E2.2` KITTI Point Perturbation attacked validation set.
- `E4.1` Track A PointPillars result at `tau=0.024`: **61.04 / 34.69**.
- Score-net checkpoint: `checkpoints/kitti/asap_score_net_trackA_v1.pth`.

## 3. Setup

### 3.1 Hardware & environment

- Machine: CUDA 12.4 node with two Tesla T4 GPUs.
- Conda env: `asap`.
- Long run policy: tmux session `asap_tau_sensitivity_e22_20260601`.
- Parallelism: two-GPU sharded purification and two-GPU PointPillars eval.

### 3.2 Data

- Dataset: KITTI val, 3769 frames.
- Attack: `E2.2` Point Perturbation.
- Detector: PointPillars.

### 3.3 Detector / defense

- Defense: Track A score-net purifier with `score_anchor_blend=0.75`.
- Baseline threshold: `tau=0.024`.
- Tested stricter thresholds: `tau=0.036`, `tau=0.048`.

### 3.4 Reproducible command

## 4. Procedure

1. Reused the KITTI E2.2 attacked validation set.
2. Ran Track A purification twice, with `tau=0.036` and `tau=0.048`.
3. Evaluated each purified set with PointPillars.
4. Parsed the resulting KITTI AP logs into `outputs/asap_tau_sensitivity/kitti_pointpillars_tau_sensitivity_summary.json`.

## 5. Expected output

- Purified outputs under `outputs/asap_tau_sensitivity/tau_0p036/` and `outputs/asap_tau_sensitivity/tau_0p048/`.
- Parsed summary JSON: `outputs/asap_tau_sensitivity/kitti_pointpillars_tau_sensitivity_summary.json`.
- Decision: keep or revise the default `tau`.

## 6. Actual results

| Setting | Car Mod AP_R40 | Cross-class mAP | Decision |
|---------|---------------:|----------------:|----------|
| Track A `tau=0.024` | **61.04** | **34.69** | Keep |
| `tau=0.036` | 59.88 | 30.21 | Worse |
| `tau=0.048` | 58.02 | 28.79 | Worse |

## 7. Analysis

The stricter thresholds do not improve sparse-class robustness. Both tested thresholds reduce Car AP and cross-class mAP, with the larger penalty in the averaged metric. This rejects the idea that simply editing fewer SPUs is enough to improve Track A. The final paper should keep `tau=0.024` and use the P2 all-unit ablation as the stronger evidence: M2 is essential, but it must be calibrated rather than manually tightened.

## 8. Issues encountered & resolutions

- No blocking runtime issue. The run used tmux and both T4 GPUs as requested.
