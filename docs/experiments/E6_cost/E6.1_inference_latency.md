## 1. Purpose / hypothesis

Measure the wall-clock cost per frame of each defense pipeline on the **same hardware that produced `E4.1`**, so that latency comparisons are directly comparable. The expected message: **ASAP's selective gating keeps purification cost below uniform SPU diffusion** while preserving detection quality (per `E4.1` and `E5.3`).

## 2. Dependencies

- `E4.1` (defines the canonical defense set: no-defense, SOR, uniform SPU, ASAP).
- `E1.1` (detector forward time on the clean scan, for reference).
- `E2.1` (attack used to populate the attacked val set being purified).

## 3. Setup

### 3.1 Hardware & environment

- The same node and GPU model used for `E4.1`.
- Single GPU; multi-GPU latency is intentionally out of scope for this experiment.

### 3.2 Frame count

- ≥ 500 KITTI val frames.
- 50 warm-up frames discarded before timing starts.

### 3.3 Reproducible command

```bash
python scripts/analyze_cost_metrics.py --out-dir outputs/cost/E6_summary
```

## 4. Procedure

1. For each defense, time three components per frame: (a) purification, (b) detector forward, (c) end-to-end including I/O.
2. Average over the 500-frame window, report mean ± std.
3. Persist a CSV under `outputs/cost/E6.1/`.

## 6. Actual results

The current numbers are derived from completed purification pipeline logs, not from a dedicated synchronized micro-benchmark. They should be described as preprocessing throughput rather than detector end-to-end latency.

| Dataset | Setting | Policy | Frames | ms/frame per GPU shard | Two-GPU aggregate throughput |
|---------|---------|--------|-------:|-----------------------:|-----------------------------:|
| KITTI | PointPillars / Injection | TrackA b075-ifilter | 3769 | 1058.5 | 529.2 |
| KITTI | PointPillars / Perturbation | TrackA b075 | 3769 | 1528.0 | 764.0 |
| KITTI | PointPillars / Dropping | Score-net diagnostic | 3769 | 1624.5 | 812.2 |
| nuScenes | Injection | ASAP-v1 | 6019 | 965.5 | 482.8 |
| nuScenes | Perturbation `eps=0.5` | ASAP-v1 | 6019 | 900.5 | 450.2 |
| nuScenes | Perturbation `eps=0.5` | ASAP-pfilter | 6019 | 963.0 | 481.5 |

## 7. Analysis

The unoptimized score-net purifier is slower than CPU SOR/ROR preprocessing, but the completed logs show consistent two-GPU throughput around **0.45-0.48 s/frame** on nuScenes and **0.53-0.81 s/frame** on KITTI depending on point count and policy. These numbers should support an honest prototype-cost paragraph, not a real-time deployment claim.
